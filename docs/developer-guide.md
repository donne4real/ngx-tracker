# NGX Tracker — Developer guide

Enough detail for a developer (or an AI assistant) to understand, maintain and extend NGX Tracker. The binding design is the [spec](superpowers/specs/2026-09-25-ngx-tracker-design.md); this guide describes the system **as built**, including changes made after the spec.

## 1. Architecture

```
                 ┌───────────────── GitHub Actions: .github/workflows/daily.yml ─────────────────┐
 Kobo Terminal ─►│ pipeline (Node/TS)                                                            │
 (daily closes)  │   kobo.ts → merge.ts → backfill.ts/eodhd.ts → metrics.ts → store.ts           │
 EODHD ─────────►│        writes data/*.json ──► git commit + push (bot)                          │
 (past year)     │ web (React/Vite) build reads data/ ──► wrangler pages deploy ──► Cloudflare   │
                 └────────────────────────────────────────────────────────────────────────────────┘
                                                            Cloudflare Pages ─► Cloudflare Access ─► browser
```

- **No server, no database.** The pipeline writes plain JSON files; the site is static and fetches them.
- **State lives in git.** `data/` is committed daily, so history is versioned and auditable.
- **Secrets never reach the browser.** Only the pipeline (in GitHub Actions) holds API keys.

## 3. Data sources

### Kobo Terminal — daily closes
- `GET https://koboterminal.com/api/ngxdata/stocks`, header `X-API-Key`. One call returns all ~146 equities.
- Response: `{ stocks[], total, total_stocks, as_of, stale_after, market }`.
  - Stock: `symbol, name, current_price, previous_close, change_percent, official_change_percent, pct_change_7d, volume, market_cap, shares_outstanding, sector, market (board), trade_date ("YYYY-MM-DDT00:00:00")`. **No open/high/low.**
  - `market`: `asi, pct_change, advancers, decliners, unchanged, trade_date, market_status ("open"|"closed"), updated_at, …`.
- Kobo treats NGX hours as 09:00–16:00 WAT; observed switching to `"closed"` at ~15:26 UTC. The status comes from a calendar (`market_status_source`), and `as_of` stops advancing when the feed stops — hence the double guard below.
- Free Personal plan: 100 requests/day, 10/min, personal use.

### EODHD — past year
- `GET https://eodhd.com/api/eod/<SYMBOL>.XNSA?period=d&fmt=json&from=…&to=…&api_token=…` → `[{date, open, high, low, close, adjusted_close, volume}]`.
- Free plan: 20 requests/day, **about 1 year** of history. Publishes with roughly a one-day lag.
- Dates verified correct against an independent source (afx.kwayisi.org, MTNN, Sep 2026). The pipeline uses unadjusted `close` to match Kobo.

## 4. Data files

### `data/history/<SYMBOL>.json`
```json
{
  "symbol": "MTNN",
  "bars": [
    {"date":"2026-09-24","close":855,"volume":1906677,"traded":true,"source":"eodhd"},
    {"date":"2026-09-25","close":863,"volume":4002657,"traded":true,"source":"kobo"}
  ]
}
```
Sorted ascending, unique dates, one bar per line (`formatHistory`) so daily diffs are one line per stock. `traded` = `volume > 0`.

### `data/stocks.json`
`{ lastTradeDate, stocks: StockMeta[] }` where `StockMeta` = `symbol, name, sector, board, marketCap, status ('active'|'inactive'), missingDays, firstKoboDate, backfill ('pending'|'done'|'failed'), backfillAttempts`.

### `data/summary.json` (compact; downloaded on every visit)
`{ asOf, generatedAt, market: {asi, pctChange, advancers, decliners, unchanged, status, noTrade}, stocks: SummaryRow[], movers: Record<Horizon,{gainers,losers}>, coverage: Record<Horizon,{eligible,total}> }`.
`SummaryRow` = `symbol, name, sector, board, status, close, volume, traded (on asOf), lastDate, historyStart, changes: Record<Horizon, number|null>, largeMove`.

### `data/report.json`
`{ runAt, outcome, tradeDate, backfill: {ok[], failed[{symbol,error}], stoppedEarly}, warnings[] }`. Outcomes: `appended`, `duplicate-date`, `market-open`, `not-final`, `backfill-only`.

## 5. The runs

### `runDaily` (weekdays; `npm run pipeline`)
1. Fetch Kobo; `parseKoboSnapshot` validates (≥100 valid stocks; symbol `^[A-Z0-9][A-Z0-9.]*$`; numeric `current_price` > 0; per-stock `trade_date` must match the market's). Invalid → throws → job fails → GitHub emails the owner. Nothing written.
2. **Close guard:** `market_status` must be exactly `"closed"` (allow-list) → else `market-open`. And `isFinalSnapshot`: `as_of` ≥ trade date + `T13:30:00Z` (NGX's official 14:30 WAT close) → else `not-final`. Nothing written in either case.
3. `trade_date` ≤ `stocks.lastTradeDate` → `duplicate-date`, nothing written, **no EODHD calls** (keeps the second daily attempt free).
4. `appendSnapshot`: one bar per stock; new symbols added (`firstKoboDate` = today, `backfill: pending`); symbols absent from the snapshot get `missingDays++` and become `inactive` at **10**.
5. Backfill (§6), `buildSummary` (§7), write all histories, stocks, summary, report.

### `runBackfillOnly` (weekends; `npm run pipeline -- --backfill-only`)
No Kobo call. If tracking has started and `summary.json` exists, backfills ≤18 stocks first seen **before today**, rebuilds the summary keeping the previous `asOf` and market figures, and writes only the touched histories plus stocks/summary/report. Nothing to do → no writes.

### Workflow logic (`daily.yml`)
- Crons: `30 15 * * 1-5`, `0 18 * * 1-5`, `0 12 * * 6,0`; plus manual `workflow_dispatch`.
- "Fetch prices": `date -u +%u` ≥ 6 → `--backfill-only`, else the daily run.
- "Detect new data": `git status --porcelain data`. Changed → commit as `ngx-tracker bot` and push.
- Build + deploy run when data changed **or** the run was manual (so a failed deploy can be retried). Deploy: `npx wrangler pages deploy web/dist --project-name ngx-tracker --branch main`.

## 6. Backfill rules (`backfill.ts`)
- `pickBackfills(file, limit=18, cutoff)`: active, `backfill === 'pending'`, `firstKoboDate < cutoff`, ordered by market cap (desc) then symbol. Cutoff = the trade date (daily) or today (weekend). **Never on a stock's first day** — EODHD lags a day, and a backfill marked done would miss the previous trading day forever.
- Range: `from = firstKoboDate − 12 months − 7 days`, `to = firstKoboDate − 1 day`.
- `mergeBackfill`: keeps only EODHD bars dated **before** the earliest existing bar / first Kobo date, so the sources never overlap.
- Errors:
  - `EodhdLimitError` (HTTP 429/402) or `EodhdUnavailableError` (401/403, 5xx, network) → stop the loop, `stoppedEarly` set, **no attempt counted**; CLI prints a `::warning::` annotation in Actions.
  - Anything else (404, empty list, bad JSON) → `backfillAttempts++`; at **3** → `backfill: 'failed'` (the stock then builds history from Kobo only).
  - EODHD errors never fail the run. Error messages never include the URL (it carries the key).

## 7. Calculations (`metrics.ts`)

`pct(now, then) = round((now/then − 1) × 100, 2 dp)`. `closeOnOrBefore(bars, date)` = the last bar with `bar.date ≤ date`.

| Horizon | Base close | Notes |
|---|---|---|
| `day` | previous stored bar | |
| `week` | on/before latest − 7 calendar days | holidays handled by "on or before" |
| `month` | on/before latest − 1 month | `minusMonths` clamps: Mar 31 → Feb 28/29 |
| `3m` / `6m` / `1y` | on/before latest − 3 / 6 / 12 months | |
| `ytd` | on/before Dec 31 of the previous year | |

- A base that doesn't exist → `null` (shown as "—").
- `traded` on a summary row = last bar is dated `asOf` **and** had volume.
- **Movers** (per horizon): active, traded today, change not null; top **10** with change > 0 (desc) and < 0 (asc); ties by symbol.
- **Coverage**: `total` = active stocks traded today; `eligible` = those with a non-null change for the horizon. The site shows "Based on N of M" when `eligible < 0.9 × total`.
- **largeMove**: |day change| > **10** (NGX's usual daily limit) → ⚠.
- **noTrade**: active stocks not traded on `asOf`.
- Site-side: **stale** when more than **4** weekdays separate `asOf` and the viewer's date (`web/src/stale.ts`); 52-week high/low and average volume over bars in (asOf − 12 months, asOf], labelled "since <date>" when history is shorter than a year (`web/src/stats.ts`).

## 8. Website
- Hash routes: `#/` (Home) and `#/stock/:SYMBOL` (`route.ts`). `base: './'` so it works from any path.
- `api.ts`: `loadSummary`, `loadHistory` (returns `null` for unknown symbols, 404, or Cloudflare's HTML fallback page).
- `horizons.ts`: the one list of period labels, typed `Record<Horizon,string>` so adding a horizon without a label fails the typecheck.
- **Backward-compatible with older data files:** missing horizons render as "—" / "Not enough history yet" rather than crashing (a newer site can be deployed next to an older `summary.json`).
- Charts: TradingView `lightweight-charts` v5 (`chart.addSeries(LineSeries, …)`), mocked in component tests.
- Responsive: `.hide-sm` (≤640 px) and `.hide-md` (≤1300 px, Sector column) classes; light/dark via `prefers-color-scheme`.

## 9. Local development
```bash
npm ci                                   # Node ≥ 22
cp .env.example .env                     # then fill in the keys
npm test                                 # pipeline + web tests
npm run typecheck
npm run pipeline -- --data-dir ../.dryrun --backfill 1   # dry run, doesn't touch data/
npm run pipeline -- --data-dir ../.dryrun --backfill-only
npm run dev -w web                       # site with the committed data/
npm run build                            # web/dist
```
`git pull` first — the bot commits to `main` daily. Don't hand-edit `data/`; if you must, do it in a PR-sized commit and re-run the pipeline.

## 10. Tests
- **Pipeline (Vitest, 60 tests):** dates, Kobo parsing/validation, merge/inactive, every horizon incl. holiday/month-end/YTD edges, movers/coverage/largeMove, EODHD parsing/errors, backfill selection/range/merge, the full `runDaily` and `runBackfillOnly` flows against a temp directory with fake fetchers (market-open, not-final, duplicate-date, limits, key rejection, 3-strike failure, first-day skip, weekend run).
- **Web (Vitest + Testing Library + jsdom, 31 tests):** api fallbacks, routing, formatting, staleness, filter/sort, table, movers tabs/coverage/caveat, stock page (not found, partial history, flags), older-`summary.json` compatibility.
- Fixture `pipeline/test/fixtures/kobo-sample.json` is a trimmed real response (no keys).
- CI (`ci.yml`) runs tests, typecheck and build on every push.

## 11. Deployment & operations
- Secrets (GitHub → Settings → Secrets → Actions): `KOBO_API_KEY`, `EODHD_API_KEY`, `CLOUDFLARE_API_TOKEN` (Account · Cloudflare Pages · Edit), `CLOUDFLARE_ACCOUNT_ID`.
- Pages project `ngx-tracker`, production branch `main`. It was created via the Cloudflare REST API because Wrangler 4.140's `pages project create` tries to delegate to Workers when it detects an AI agent and the project doesn't exist. CI deploys (no agent, project exists) use classic Pages.
- Cloudflare Access self-hosted app covers **both** `ngx-tracker.pages.dev` and `*.ngx-tracker.pages.dev` (per-deploy preview URLs). Verify with `curl -sI https://ngx-tracker.pages.dev/data/summary.json` → `302` to `…cloudflareaccess.com`.
- The bot's pushes use `GITHUB_TOKEN`, which by design doesn't trigger other workflows.

## 12. Security
- Keys only in `.env` (git-ignored) and GitHub secrets; never in `data/`, logs, error messages or the built site. Kobo's key travels in a header; EODHD's is in the URL, so its errors never echo the URL.
- Symbols are validated before being used in file paths (pipeline) or URLs (web).
- The whole site, including `data/*.json` and preview deployments, is behind Cloudflare Access.
- Data licensing: free plans are personal-use. Going public or commercial requires a licensed plan.

## 13. Design decisions & history
| Decision | Why |
|---|---|
| Static site + scheduled job, no server/DB | $0, nothing to keep running, history versioned in git |
| Kobo daily + EODHD one-off backfill | All stocks current daily for free; a year of history without paying |
| Allow-list `"closed"` + `as_of` after close | Kobo's status is calendar-based; never store an intraday price as a close |
| Skip backfill on a stock's first day | EODHD lags a day; avoids a permanent one-day gap |
| Pause (not fail) on EODHD key/outage errors | A bad key shouldn't silently mark every stock failed |
| Coverage note on movers | During backfill, rankings only cover a subset |
| Weekend history-only runs | EODHD quota is per calendar day; halves the fill-up time |
| Manual run always redeploys | Recover from a failed deploy after data was already committed |
| Tolerate older `summary.json` | A newer site must never render blank next to older data |

Build history: v1 built Sep 25, 2026 (plan Tasks 1–10, independent review, 5 fixes, go-live); 3M/6M/YTD/1Y and weekend runs added the same day.

## 14. Extending it
- **New horizon:** add to `Horizon` (types.ts) and `HORIZONS` (metrics.ts), compute it in `computeChanges`, add the label in `web/src/horizons.ts` (the typecheck enforces it), add table cells in `StockTable.tsx`; write tests first.
- **Swap/upgrade the data source:** only `kobo.ts` (parsing into `Snapshot`) and `eodhd.ts` should change; everything downstream uses the internal types.
- **Watchlists, alerts, dividends/total return, corporate-action adjustment** are out of scope for v1 — see the spec's out-of-scope list.
